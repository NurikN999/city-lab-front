# city-lab-front

React 19 + TypeScript 6 + Vite 8. Хакатон-проект: скорость важна, но код должен читаться с первого раза.

## Команды

- `npm run dev` — dev-сервер
- `npm run build` — `tsc -b` + сборка (это и есть проверка типов)
- `npm run lint` — ESLint

Перед тем как сказать «готово»: `npm run build && npm run lint` должны проходить без ошибок.

## Общие принципы

- Самое простое решение, которое работает. Нет абстракций «на будущее», нет обёрток над одной реализацией.
- Сначала платформа: нативный HTML (`<dialog>`, `<details>`, `<input type="date">`, `<form>`) и CSS, потом JS, потом новая зависимость.
- Новую npm-зависимость добавлять только если без неё — больше ~50 строк нетривиального кода. Проверить размер (bundlephobia) и что пакет жив.
- Не трогать код вне задачи. Никаких попутных рефакторингов.

## Структура

```
src/
  app/          # корень: App, провайдеры, роутинг
  features/     # фича = папка: components/, hooks/, api.ts, types.ts
  shared/       # переиспользуемое 2+ фичами: ui/, hooks/, lib/
  assets/
```

- Код живёт в фиче, пока его не использует вторая фича — тогда переносится в `shared/`.
- Фичи не импортируют друг из друга напрямую; общее — через `shared/`.
- Без barrel-файлов (`index.ts` с реэкспортами) — ломают tree-shaking и HMR.
- Один компонент — один файл. Имя файла = имя компонента: `UserCard.tsx`. Хуки: `useSomething.ts`. Остальное: `camelCase.ts`.

## TypeScript

- `any` запрещён. Неизвестные данные — `unknown` + сужение типа.
- Не использовать `as` для «успокоения» компилятора. `as const` и `satisfies` — можно.
- Ненулевой `!` только когда инвариант очевиден из соседней строки.
- `import type { X }` для типов (требует `verbatimModuleSyntax`).
- `erasableSyntaxOnly` включён: **нет `enum`, `namespace`, parameter properties**. Вместо enum — union строк: `type Status = 'idle' | 'loading' | 'error'`.
- `type` по умолчанию; `interface` — только если нужно расширение.
- Пропсы типизировать напрямую: `function Button({ label }: ButtonProps)`. Без `React.FC`.
- Состояния с вариантами — discriminated union, а не набор булевых флагов:
  `{ status: 'success'; data: T } | { status: 'error'; error: string }`.
- Данные с сервера — граница доверия: валидировать форму ответа, а не кастовать `as User`.

## React

Правила из [react.dev](https://react.dev/reference/rules) и [You Might Not Need an Effect](https://react.dev/learn/you-might-not-need-an-effect):

- Компоненты и хуки — чистые функции. Никаких мутаций пропсов/state, никаких side effects в рендере.
- **Производное — вычислять в рендере**, не хранить в state и не синхронизировать через `useEffect`.
- `useEffect` — только для синхронизации с внешней системой (DOM API, подписки, сокеты). Реакция на действие пользователя — в обработчике события.
- Сброс state при смене сущности — через `key`, а не эффект.
- Каждый эффект с подпиской возвращает cleanup.
- Минимальный state; поднимать его только до ближайшего общего родителя. Глобальный стор — только когда prop drilling реально мешает (3+ уровня).
- `useMemo` / `useCallback` / `memo` — только при измеренной проблеме производительности, не по умолчанию.
- Списки: стабильный `key` из данных (`id`), никогда не индекс массива, если порядок может меняться.
- Не объявлять компоненты внутри других компонентов.
- Кастомный хук — когда логика с хуками повторяется или загромождает компонент. Хук возвращает данные, а не JSX.
- Формы в React 19: `<form action={fn}>`, `useActionState`, `useFormStatus` вместо ручного `onSubmit` + `useState` для pending.
- Все асинхронные данные показывают три состояния: загрузка, ошибка, пусто.
- Экспорт: named exports. `export default` — только где требует инструмент (lazy-роуты).

## Данные и API

- Все запросы — через один модуль клиента (`shared/lib/api.ts`), базовый URL из `import.meta.env.VITE_API_URL`.
- Секреты не хранить во фронте: всё с префиксом `VITE_` попадает в бандл.
- Запросы в эффектах отменять через `AbortController` в cleanup (гонки при быстрой смене параметров).
- Ошибки не глотать: пустой `catch {}` запрещён. Либо показать пользователю, либо пробросить.

## Стили

- CSS-переменные для цветов, отступов, радиусов — в `:root` (`src/index.css`). Хардкод цветов в компонентах запрещён.
- Стили компонента — CSS Modules (`Button.module.css`), чтобы классы не конфликтовали.
- Mobile-first: базовые стили для узкого экрана, `@media (min-width: …)` для широкого.
- Layout — flex/grid с `gap`, а не margin-хаки. Единицы — `rem` для типографики и отступов.
- Инлайн `style={}` — только для динамических значений (координаты, прогресс).
- Уважать `prefers-reduced-motion` для анимаций.

## Доступность (не упрощать)

- Семантика первична: `<button>` для действий, `<a href>` для навигации, `<nav>`, `<main>`, `<header>`, заголовки по порядку. `<div onClick>` запрещён.
- У каждого `<input>` есть `<label>`. У иконки-кнопки — `aria-label`.
- `<img>` всегда с `alt` (пустой `alt=""` для декоративных).
- Всё работает с клавиатуры, фокус виден (не убирать `outline` без замены).
- Контраст текста ≥ 4.5:1 (WCAG AA).
- ARIA — только когда нет нативного элемента.

## Производительность

- Роуты грузить лениво: `lazy(() => import('./Page'))` + `<Suspense>`.
- Изображения: указывать `width`/`height`, `loading="lazy"` ниже первого экрана, современные форматы (webp/avif).
- Не импортировать библиотеку целиком ради одной функции.

## Безопасность

- `dangerouslySetInnerHTML` — запрещён без санитизации (DOMPurify).
- Пользовательские URL в `href` проверять на протокол (`javascript:`).
- Токены — не в `localStorage`, если бэкенд может выдать httpOnly cookie.

## Именование

- Компоненты, типы: `PascalCase`. Переменные, функции: `camelCase`. Константы-конфиги: `UPPER_SNAKE_CASE`.
- Булевы: `is/has/can/should` — `isOpen`, `hasError`.
- Обработчики: проп `onSelect`, реализация `handleSelect`.
- Имена описывают смысл, не тип: `users`, а не `usersArray`.
